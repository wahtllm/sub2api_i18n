# 多语言维护手册（私有 fork 版）

本仓库是 [Wei-Shaw/sub2api](https://github.com/Wei-Shaw/sub2api) 的私有 fork，
在官方 en / zh 之外新增了 5 门 UI 语言：**日语 (ja)、德语 (de)、韩语 (ko)、西班牙语 (es)、巴西葡语 (pt-BR)**。

## 支持的语言与探测逻辑

`frontend/src/i18n/index.ts`：

- 语言选择持久化在浏览器 `localStorage`（key: `sub2api_locale`）。
- 首次访问按浏览器语言前缀探测：`zh / ja / de / ko / es / pt`（所有葡语变体归 `pt-BR`），其余回落英文。
- 缺失的 key 自动回落英文（`fallbackLocale: 'en'`）。

## 文件结构

```
frontend/src/i18n/locales/{en,zh,ja,de,ko,es,pt-BR}/   # 7 套语言包，结构完全镜像
frontend/i18n-glossary/{ja,de,ko,es,pt-BR}.md          # 各语言术语表 + 文体规范（翻译必读）
frontend/src/i18n/__tests__/                           # 质量闸门（见下）
```

## 质量闸门（勿绕过）

`pnpm run build`（以及 CI 的 Docker 构建）会先跑 `check:i18n`，强制校验全部 7 种语言：

1. **key 结构与 en 完全一致**（多一个少一个都失败）；
2. 所有文案为非空字符串；
3. 代码中静态引用的每个 key 在 7 种语言里都存在；
4. 所有文案能通过 vue-i18n 消息编译（占位符 `{xxx}`、`{'{'}` 转义不被破坏）。

## 升级官方新版本的流程

```bash
git fetch upstream
git merge upstream/main
# 如 i18n/index.ts 或 __tests__ 有冲突：保留双方新增内容即可
#（新语言目录官方不存在，永远不会冲突）

cd frontend && npx pnpm@9 exec vitest run src/i18n
# 测试会精确列出 ja/de/ko/es/pt-BR 各缺了哪些 key（官方新版本会给 en/zh 加新 key）

# 按测试报错补翻译缺失的 key（对照 frontend/i18n-glossary/<lang>.md 术语表），
# 直到测试全绿，然后：

git push            # CI 自动构建新镜像 → ghcr.io/wahtllm/brushllm_sub2api_i18n
```

服务器更新：`docker compose pull && docker compose up -d`（数据在 volume，语言选择在浏览器，均不受影响）。

### 拉取私有镜像

私有仓库的 ghcr.io 镜像需要登录。在服务器上：

```bash
echo "<GitHub PAT (read:packages)>" | docker login ghcr.io -u wahtllm --password-stdin
```

compose 中把 `image: weishaw/sub2api:latest` 换成 `image: ghcr.io/wahtllm/brushllm_sub2api_i18n:latest`。
（首次构建后也可在 GitHub Packages 设置里把该 package 改为 public，即可免登录拉取。）

## 再添加一门新语言（以 fr 为例）

1. 复制 `frontend/src/i18n/locales/en/` 整目录为 `locales/fr/`（`index.ts` 与 `admin/index.ts` 无需改动，相对导入自动生效）；
2. 按 `frontend/i18n-glossary/` 现有格式新建 `fr.md` 术语表；
3. 翻译其余 16 个文件的字符串值（key、结构、占位符、HTML 标签、配置项名称保持原样）；
4. `frontend/src/i18n/index.ts` 四处扩展：`LocaleCode` 类型、`LOCALE_CODES`、`localeLoaders`、`availableLocales`（如需浏览器自动探测，再加 `browserLocaleMatchers` 条目）；
5. `frontend/src/i18n/__tests__/localeKeyCompleteness.spec.ts` 与 `localesMessageCompile.spec.ts` 各加一条 import / 一条用例；
6. `npx pnpm@9 exec vitest run src/i18n` 全绿即可。

## 已知的非 i18n 硬编码（二期项）

以下组件为 `zh ? 中文 : 英文` 的二元逻辑，新语言自动回落英文分支，功能不受影响：

- `components/common/DateRangePicker.vue`（日期格式 zh-CN / en-US）
- `views/KeyUsageView.vue`（时间窗口标签 日/D）
- `components/AliyunCaptchaWidget.vue`、`components/TencentCaptchaGate.vue`（验证码语言）
- `components/admin/AdminComplianceDialog.vue` 与 `stores/adminCompliance.ts`（合规法律文档仅有中英版本，需专业翻译后再扩展）

邮件模板按 locale 存于数据库，可在管理后台为任意语言添加；支付页语言由 `Accept-Language` 头自动透传。
